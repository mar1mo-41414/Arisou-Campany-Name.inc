# 仕組み — どうやって「ありそう」を作っているか

対象読者は開発者です。利用者向けの説明は [README.md](../README.md)、各ルールの意味は
[RULES.md](RULES.md)、作業方針は [AGENTS.md](../AGENTS.md) にあります。

## 1. 全体の流れ

```
ブラウザ
  index.html
    └─ app.js          ルールを読む → generator.generateNames(options) → DOM に並べる
         └─ generator.js
              normalizeOptions()  入力を検証・丸める
              makeRng(seed)       シードから再現可能な乱数を作る
              generateOne()       本体を組み立て、文字数条件を満たすまで引き直す
              applyCorp()         法人種別を前か後ろに付ける
```

- 生成はすべて同期・ローカル。`fetch` も `XMLHttpRequest` も使っていない。
- `generator.js` は UI を知らない。Node から `require()` しても同じ結果になる（テストはこれを使う）。
- `index.html` は `<script src="generator.js">` と `<script src="app.js">` の2本だけ読む。
  ES モジュールにしていないのは、`file://` で開いたときに CORS で止まるため。
- 一度に生成する上限は 20 件（`generator.js` の `MAX_COUNT`、`app.js` の `MAX_COUNT`、
  `index.html` の `input max` の3か所で管理）。

## 2. 名前の構造

```
[ 地名 ]  [ 主語 ]  [ 数字 ]  [ 業種接尾辞 ]
  任意      必須     任意       任意
```

例:

| 名前 | 地名 | 主語 | 数字 | 接尾辞 | 法人種別 |
| --- | --- | --- | --- | --- | --- |
| 株式会社対馬明星 | 対馬 | 明星 | — | — | 前株 |
| 姪浜東栄株式会社 | 姪浜 | 東栄 | — | — | 後株 |
| 株式会社千歳製作所 | — | 千歳 | — | 製作所 | 前株 |
| 株式会社青葉88建設 | — | 青葉 | 88 | 建設 | 前株 |
| 株式会社コスモス電子 | — | コスモス | — | 電子 | 前株 |

「本体（`core`）」は地名〜接尾辞まで。文字数の条件はこの `core` に対して判定する。
法人種別は最後に付けるだけなので、`株式会社` を選んでも文字数は増えない扱いになる。

## 3. 語彙

| 配列 | 中身 | 例 |
| --- | --- | --- |
| `KANJI_WORDS` | 漢語の主語 | 大成, 明和, 瑞光, 金光, 千歳, 白鷺 |
| `REGIONS` | 地名・地域名 | 博多, 霧島, 有明, 玄海, 東京 |
| `KATA_WORDS` | カタカナの主語 | コスモス, グランツ, シリウス, メルカート |
| `HIRA_WORDS` | ひらがなの主語 | はやぶさ, こもれび, ほたる, まほろば |
| `EN_WORDS` | 英字の主語 | SUNRISE, VERTEX, POLARIS, MERIDIAN |
| `INDUSTRIES` | 業種ごとの接尾辞（漢字・カタカナ・英字の3系統） | 商事 / トレーディング / TRADING |
| `DIGITS` | 名前に挟む数字 | 88, 21, 100, 365, 2, 3 |

すべて `[表記, よみ]` の組で持っている。カードに出す「よみがな」はここから組み立てる。
英字の語彙は読みをカタカナで持たせている（英字のままよみを出しても意味がないため）。

## 4. 確率（ここが「ありそう」の調整つまみ）

数字は `generator.js` の現在値。変えたらこの表も直す。

| 箇所 | 値 | 意図 |
| --- | --- | --- |
| 漢字の主語で地名を頭に付ける | 30% | 付けすぎると「地名＋地名」に見える |
| 業種接尾辞を付ける | 55%（ひらがなの主語のとき 18%） | ひらがな＋漢字接尾辞は少数派なので抑える |
| 本体が `製作所` `工務店` `不動産` 等で終わるときの後株 | 5% | 「千歳製作所株式会社」の二重接尾辞を避ける |
| 自動モードでの後株 | その他 30% | 現実に前株のほうが多い |
| 名前に数字を入れる（数字オプション時） | 50% | 毎回入ると不自然 |
| 英字の大文字小文字を混ぜる | 35% | `Stride` のような形。全部大文字ばかりにしない |

上から順に「不自然さが出やすい順」に並んでいる。新しい条件を足すときも、
**不自然な組み合わせを確率で避ける**方針を取る（禁止して組み合わせを減らすより、頻度を下げる）。

避けている組み合わせ（ハードコード）:

- ひらがなの主語 ＋ 英字の接尾辞
- 英字の主語 ＋ 漢字の接尾辞
- ひらがなを接尾辞の文字種に選ばない

## 5. 文字数の調整

`generateOne()` は条件を満たす名前が出るまで最大 400 回引き直す。
400 回で出なければ「条件に一番近いもの」を返し、`satisfied: false` を立てる。
`generateNames()` は1件でも `satisfied: false` があれば `unmetLength: true` を返し、
UI が「条件では文字数に収まらなかった」と警告する。

**黙って0件を返さない**のが方針。条件が厳しい（例: 英字だけ・1〜2文字）ことはあるので、
空振りより「近いもの＋警告」のほうが使える。

## 6. 重複の扱い

`generateNames()` は `core` を大文字化したものをキーにして重複を弾く。
`full` で判定すると「株式会社◯◯」と「◯◯株式会社」が別物として両方出てしまうため。

1回の生成で最大 `count × 80` 回まで試す。語彙が尽きて `count` 件に届かないこともある
（その場合は返せる分だけ返す）。上限は 20 件なので、最悪でも 1,600 回の試行で終わる。

## 7. 再現性（シード）

```
seed → FNV-1a で 32bit ハッシュ → mulberry32
```

`generator.js` の中では `Math.random()` を呼ばない。`app.js` がシードを作るときだけ使う。
シードは URL の `?seed=` でも渡せるので、同じ結果を共有できる。

UI 側の扱い（`app.js`）:

| シード欄 | 挙動 |
| --- | --- |
| 空 | 生成のたびに `randomSeed()` で新しいシードを振る。結果はそのつど変わる |
| 値あり | そのシードに固定。押し直しても同じ結果 |

生成に使ったシードは結果の下に表示し、「固定する」で欄へ戻せる。

> 注意: 語彙や確率を変えると、同じシードでも結果は変わる。シードが保証するのは
> 「同じバージョンの同じ実装で同じ結果」まで。

## 8. 拡張するとき

### 語彙を足す

該当する配列に `['表記', 'よみ']` を足すだけ。テストは通る。
ただし `docs/RULES.md` の例が古くなるので、必要なら直す。

### 業種を足す

`INDUSTRIES` にオブジェクトを足す。`kanji` / `kata` / `en` を**3系統とも**用意する。
1つでも欠けると、その文字種では接尾辞候補が空になり、選んだのに接尾辞が出ない状態になる。

### ルールを足す

1. `generator.js` の `DEFAULT_OPTIONS` と `normalizeOptions()` に足す
2. `buildCore()` / `applyCorp()` に反映
3. `index.html` にコントロールを足し、`app.js` の `readOptions()` で読む
4. `test/generator.test.js` に、そのルールが守られることのテストを足す
5. README のルール説明と `docs/RULES.md` を更新

## 9. やらないこと

- 実在企業データベースとの照合（「実在しないこと」は保証しない。するつもりもない）
- 商標調査、ドメイン空き確認（外部通信が必要になる）
- 生成結果のサーバー保存（保存するなら localStorage。外部送信はしない）
